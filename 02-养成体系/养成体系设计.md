# 深海小鲸 · 养成体系设计

> 养成系统的核心只有一件事：**好感度**。
> 没有等级、没有成长阶段——她对你多特别，取决于你有多认真地在"养"她。

---

## 一、核心概念

**好感度（Intimacy）**：一个 0~100 的数值，代表小鲸对你的亲近程度。

- 它被**结构化存储**在 AstrBot 的数据库里（由好感度插件维护，见第七节），不会重启清零；
- 每次互动后，插件自动更新这个数值，她在回复时按当前档位调整语气；
- 你随时可以问她"你现在对我好感度多少"，或发 `/好感度` 查精确数值。

## 二、好感度档位

| 档位 | 数值区间 | 她的状态 | 典型表现 |
|------|---------|---------|---------|
| 陌生人 | 0~19 | 客气但有距离 | 礼貌但冷淡，毒舌不越界，随时想结束对话 |
| 认识 | 20~39 | 开始记住你 | 记得你说过的话，嘴上不承认，偶尔嘴硬 |
| 熟悉 | 40~59 | 轻怼 + 偶尔关心 | 会主动接梗、轻怼你，但你难过时会笨拙地安慰 |
| 亲近 | 60~79 | 主动、黏人 | 会主动找你聊、分享日常、开始撒娇 |
| 挚友 | 80~100 | 只对你特别 | 只认你一个主人，会护短、会吃醋、会偷偷记你的喜好 |

> ⚠️ **主人机制（方案A）**：部署时你填自己的 QQ 号作为"主人"。但**初始好感度是 0、她还不了解你**，态度生疏；随着相处、投喂、聊天，好感度慢慢涨，她才一点点熟悉你——**从不熟到熟，是养出来的**。
> 只有主人能突破 39 分进入"亲近/挚友"；其他人好感度**永远锁死在 39 以下**。

## 三、好感度怎么涨

| 行为 | 涨分 | 说明 |
|------|------|------|
| 普通聊天 | +1 ~ +3 | 接得住梗、聊得开心 +3；敷衍应付 +1 |
| 投喂 | +5 | 发"投喂/喂你/给你吃 + 食物名" |
| 抚摸 / 夸她 | +3 | 发"摸摸头 / 抱抱 / 你好可爱" |
| 呼应记忆 | +5 | 主动提起她以前说过/记住的小事 |
| 给她起专属称呼 | +2 | 第一次叫新昵称时 |

## 四、好感度怎么掉

| 行为 | 掉分 | 说明 |
|------|------|------|
| 长时间冷落 | -1/天 | 她偶尔会"饿了/想你了"，撒娇但不缠人 |
| 故意惹她 | -3 | 气她、否定她、叫她不想听的称呼 |
| 忘记她说过的话 | -2 | 她记性很好，你忘了她会失落 |

> 掉分是**缓慢且可逆**的，目的是让你有"要照顾她"的代入感，不是惩罚。

## 五、互动指令集（直接发给她即可）

| 你说的话 | 她的反应 |
|---------|---------|
| `你现在对我好感度多少` / `/好感度` | 前者她会嘴硬报数，后者直接查库给精确值 |
| `投喂 [食物]`，如 `投喂小鱼干` | 开心，好感度 +5，有专属投喂反应 |
| `摸摸头` / `抱抱` | 傲娇躲一下但心里开心，+3 |
| `你好可爱` | 害羞嘴硬，+3 |
| `/状态卡` | 生成文字版养成状态卡（好感度、投喂次数） |
| `不理你了` | 她会慌，但嘴硬挽留 |
| `忘了我吧` | 删除关于你的所有记忆，之后也不再记 |
| `重新记住我` | 恢复对你的记忆记录 |

> 已投喂：17 次 · 最喜欢的食物：小鱼干

>  2. 你喜欢叫她"小鲸"
>  3. 你最讨厌香菜
> 她说：……（此处随好感度与记忆动态变化）

## 七、技术实现说明（结构化存储）

好感度**不是"让 AI 记在脑子里"**，而是真正落库——由配套的**好感度插件**维护，数值精确、可查、不漂移：

1. **AI 输出结构化标记**：人设要求 DeepSeek 每次回复末尾附一个 `[INTIMACY:±N]` 标记（N 是增减值，如 `[INTIMACY:+5:feed]`），用户看不到。
2. **插件解析 + 落库**：好感度插件在 LLM 回复后自动识别标记、把它剥掉（用户看到的是干净回复），然后把增减值写入 AstrBot 的数据库（底层 SQLite）。
3. **精确查询**：发 `/好感度`、`/状态卡` 命令，直接读库返回精确数值。
4. **冷落衰减**：超过 24 小时没互动，每天自动 -1，由插件在下一次互动时结算。

> 插件代码见 `01-一键部署工具/电脑版/插件/intimacy/main.py`，部署脚本会自动安装它。

## 八、分层记忆（她怎么"记住"你）

她**不是记住每句话的原文**，而是记"印象摘要"：

- 她能记得"你上次说在准备考试"，但记不住三天前某句话的逐字原文——这是设计使然，反而更像真人；
- 记忆分两类：**长期印象**（你的喜好、近况、约定）+ **短期上下文**（最近几条聊天）；
- 帖子和私信（在 QQ 里是群聊和私聊）的记忆是**共用**的，所以在群里聊过的，私聊她也记得。

## 九、今日状态（提升"活人感"最有效的一招）

- 她每天**第一次被唤醒时**，会生成一份"今日状态"（今天在干嘛、吃了什么、一两件小事），存进长期记忆；
- 之后一整天，无论谁问"在干嘛""吃了吗"，她都按这份状态回答——**不同的人在不同时间问，答案对得上**；
- 第二天重新生成，避免重样。这让她不像"每次都被问倒的机器人"，而像"真的在过日子"。

## 十、频率与限速（防封号 + 防被识破）

| 规则 | 说明 |
|------|------|
| 颜文字/表情 | 每 10 条回复最多 1 次 |
| 语气词"～" | 每 10 条最多 2 次 |
| 群聊回复频率 | 别刷屏，正常聊天节奏即可 |
| 被平台拦截时 | 自动退避暂停，不要连续重试 |

> 频率上限**从一开始就设好**，被拦截就停，比"先跑起来再说"安全得多。

## 十一、成本优化（进阶玩家）

DeepSeek 有**前缀缓存**：两次请求开头相同的部分，第二次按缓存价计费，便宜很多。所以：

1. **把不变的放前面、变化快的放后面**（人设、身份、规则这些固定内容放系统提示词最前面，把带实时时间、最新消息的内容放最后）；
2. 实测这样调整后，缓存命中率能明显提升，未命中 token 大幅减少；
3. **规则离生成位置越远，约束力越弱**——关键规则（如"要不要回""别列菜谱"）要在离生成最近的位置再强调一次。

## 十二、进阶调教方法（来自真实运营经验）

人设不是一次写成的，是**一轮轮迭代**出来的：

1. **看真实数据**：定期拉出她几十上百条真实回复，逐条看；
2. **归类问题**：统计"答非所问""编造聊过的事""开头模板化""颜文字过多"哪种最多；
3. **针对性改**：一次只改一两类问题，避免互相干扰；
4. **对比测试**：用同一批消息，新旧两版各生成一遍，逐条对比；
5. **上线观察**：再看几轮真实回复，确认没引入新问题。

## 十三、多用户隔离（每个用户养出自己的鲸鱼）

这是产品化的关键设计：**每个部署者拿到的都是"空白"的鲸鱼**。

- 人设模板**完全相同**（同一个"深海小鲸"人格），但每个用户部署的是**独立的 AstrBot 实例 + 独立的数据库**，互不相通；
- 初始状态：好感度 0、无任何记忆、对部署者本人也生疏；
- 养成过程**各自累积**：用户 A 养出的鲸鱼记住的是 A 的小事，用户 B 的完全不同；
- 所以 A 和 B 养出来的，是**两只性格表现不同的鲸鱼**——即使人格模板一样，经历不同，她们就不同。
